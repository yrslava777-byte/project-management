# Тексты для плана работ

Создайте карточки в своём проекте. Замените ссылки в квадратных скобках адресами своих задач, имена — выбранными ответственными. Обозначения А1, А2, Б, В, Г используются для связи работ в плане.

В задаче В каждый пункт блока добавьте отдельным пунктом чек-листа. Его выполнение относится к будущей работе. Все новые карточки оставьте незавершёнными.

## Общая задача: название

```text
Подготовить резервирование последнего рюкзака
```

## Общая задача: описание

```text
Будущий результат: согласованная работа создания резерва и обработки его срока, отмены и оплаты для последнего рюкзака.

Основание: требования R1–R5 версии 2 из задачи «Подготовить проверки последнего товара».
Источник требований и P1–P5: [ссылка на существующую задачу из темы 3].

Работы внутри задачи:
— создать резерв при подтверждении оформления;
— обработать срок, отмену и оплату резерва.

Условия приёмки: обе части реализованы; при доступном количестве 1 резерв получает только один заказ. Новый неоплаченный резерв действует 20 минут. Отмена и окончание срока освобождают неоплаченный резерв, но не возвращают в продажу оплаченный товар.

Для общего результата нужны также интерфейс покупателя и сквозная проверка. Они планируются отдельными задачами проекта.

Границы: один рюкзак, количество 1. Поздняя оплата, возврат оплаченного товара, частичное выполнение заказа и переход уже созданных резервов на новый срок не входят в работу.

Статус на занятии: составляем план будущей работы. Реализация и тестирование программы не выполнены.
```

## А1: название

```text
Создать резерв при подтверждении оформления
```

## А1: описание

```text
Будущий результат: при подтверждении оформления система проверяет доступный остаток и создаёт резерв одной неделимой операцией. Корзина сама резерв не создаёт.

Требования: R1, R2 версии 2.
Источник: [ссылка на задачу темы 3].

Условия приёмки:
— при добавлении единственного рюкзака в корзину резерв не создаётся;
— при подтверждении оформления создаётся один резерв, доступный остаток становится 0;
— два одновременных оформления при остатке 1 не создают два успешных резерва;
— при недоступном товаре другой заказ не подтверждается.

Передача результата: описаны данные, по которым обработка оплаты и интерфейс отличают успешный резерв от отказа. Эти сведения согласуются с исполнителями связанных задач до их реализации.

Связанные проверки: P1, P2 и дополнительный сценарий одновременного оформления из темы 3. Их прогон запланирован отдельно.

Работа относится к общей задаче о резервировании. Заполнение карточки не означает, что резервирование реализовано.
```

## А2: название

```text
Обработать срок, отмену и оплату резерва
```

## А2: описание

```text
Будущий результат: состояния резерва меняются по согласованным правилам срока, отмены и подтверждения оплаты.

Требования: R3, R4, R5 версии 2.
Источник: [ссылка на задачу темы 3].

Условия приёмки:
— новый неоплаченный резерв действует 20 минут с момента создания;
— через 16 минут без оплаты и отмены резерв ещё действует;
— через 21 минуту без оплаты резерв снят, товар снова доступен;
— отмена неоплаченного заказа до окончания срока освобождает резерв;
— оплата, подтверждённая до окончания срока, закрепляет товар за заказом;
— наступление прежнего срока окончания не освобождает оплаченный товар.

Для реализации нужны данные создаваемого резерва: его связь с заказом, время создания и состояние. Сначала согласовать их с исполнителем подзадачи о создании резерва. Проверка совместной работы возможна после появления обеих частей.

Связанные проверки: P3, P4, P5 версии 2. Здесь планируется реализация, а не повторное написание сценариев.

Границы: поздняя оплата и переход уже созданных резервов на новый срок не входят в работу.
```

## Б: название

```text
Показать покупателю результат оформления
```

## Б: описание

```text
Будущий результат: покупатель различает успешное оформление и отказ из-за недоступности товара.

Требование: R2. Связанное основание: R1.
Источник: [ссылка на задачу темы 3].

Условия приёмки:
— при успешном оформлении показано подтверждение заказа;
— если доступного товара нет, показано «Товар временно недоступен»;
— отказ не показан как успешный заказ;
— вывод соответствует фактическому ответу операции создания резерва.

Порядок: варианты отображения и обработку ответов можно готовить параллельно с созданием резерва после согласования формата его результата. Совместную работу проверять после готовности операции создания резерва.

Зависимость: [ссылка на А1].
Проверки поведения: P1 и P2. Фактический сквозной прогон запланирован в отдельной задаче.
```

## В: название

```text
Подготовить данные для проверки резервирования
```

## В: описание

```text
Будущий результат: подготовлено описание тестовых данных и порядка восстановления исходного состояния для независимого прогона P1–P5 версии 2 и дополнительного сценария одновременного оформления.

Источник сценариев и требований: [ссылка на задачу темы 3].

Нужно определить один товар с доступным количеством 1, двух покупателей, отдельные заказы и начальное состояние каждого сценария. Указать, как воспроизвести моменты 5, 10, 16 и 21 минута в будущей тестовой среде. Для одновременного оформления определить способ отправить два конкурирующих запроса и подсчитать успешные резервы.

Условия приёмки: для каждого сценария известно, что подготовить до запуска и как восстановить состояние перед следующим. Моменты времени отсчитываются от создания резерва конкретного сценария. Данные одного прогона не переходят в другой.

Работу над описанием данных можно начать сразу по согласованным сценариям. Создание самих данных и настройка управления временем потребуют будущей тестовой среды; её отсутствие нужно явно отметить, а не изображать готовый прогон.

На занятии создаём только план этой работы. Подготовленный ранее текст P1–P5 сохраняем и не переписываем.
```

## В: пункты чек-листа

```text
Описать товар с доступным количеством 1 и двух покупателей
Определить отдельное исходное состояние для каждого P1–P5
Указать способ наблюдать состояния на 5, 10, 16 и 21 минуте
Определить способ проверить два одновременных оформления
Указать восстановление исходного состояния перед каждым сценарием
Отметить, что нельзя подготовить без будущей тестовой среды
```

## Г: название

```text
Выполнить сквозную проверку резервирования
```

## Г: описание

```text
Будущий результат: протокол фактического прогона P1–P5 версии 2 и дополнительного сценария одновременного оформления на работающей тестовой версии магазина.

Покрытие: R1–R5 версии 2.
Источник требований и сценариев: [ссылка на задачу темы 3].

Условия начала прогона: доступны создание резерва, обработка срока/отмены/оплаты, интерфейс покупателя и подготовленные данные. Проверяем именно их совместную работу.

Входные результаты:
— [ссылка на А1];
— [ссылка на А2];
— [ссылка на Б];
— [ссылка на В].

Условия приёмки: для каждого сценария указаны исходные данные, действие, ожидаемый и фактический результат. При расхождении сохранены шаги воспроизведения. Если сценарий нельзя запустить, записана причина блокировки; он не считается успешным.

Особое внимание: через 16 минут неоплаченный резерв действует; через 21 минуту без оплаты снят; после оплаты на 10-й минуте товар не возвращается в продажу на 21-й минуте.

Каждый сценарий начинается независимо. Проверка одновременных оформлений не заменяется двумя последовательными действиями.

На этой паре протокол не создаём: работающая программа не предоставлена. Созданная карточка — часть плана, а не свидетельство успешных тестов.
```

## В чат общей задачи: порядок работ

```text
Порядок работ по резервированию

Источник: требования R1–R5 и P1–P5 версии 2 — [ссылка на задачу темы 3].

А1 — создание резерва: [ссылка]. Ответственный: [имя выбранного участника].
А2 — срок, отмена и оплата: [ссылка]. Ответственный: [имя выбранного участника].
Б — интерфейс покупателя: [ссылка]. Ответственный: [имя выбранного участника].
В — данные для проверки: [ссылка]. Ответственный: [имя выбранного участника].
Г — сквозная проверка: [ссылка]. Ответственный: [имя выбранного участника].

Можно начать сразу: А1 и описание данных В. Для В уже есть требования и сценарии; ждать готовой страницы не нужно.

До реализации А2 и Б исполнители согласуют с А1 данные резерва и различие успешного ответа и отказа. После этого подготовка этих частей может идти параллельно. Проверка их совместной работы требует готовых частей.

Г начинается, когда доступны результаты А1, А2, Б, В и работающая тестовая среда. Если чего-то нет, фиксируем конкретную причину ожидания.

Подзадачи А1 и А2 входят в общую задачу. Это группировка, а не указание выполнить А2 строго после полного завершения А1.

Все перечисленные работы пока запланированы. Реализация и фактические тесты на занятии не выполнялись.
```
